# Разработка

[← Главная документация](../README.md)

Инструкции по работе с исходниками и подготовке изменений к PR. Все команды выполняются из корня проекта.

## Команды

| Команда                        | Назначение                                                            |
| ------------------------------ | --------------------------------------------------------------------- |
| `npm run dev`                  | Запуск сервера разработки Vite.                                       |
| `npm run build`                | Проверка TypeScript и production-сборка в `dist`.                     |
| `npm run preview`              | Локальный просмотр уже собранного `dist`.                             |
| `npm run lint`                 | Проверка ESLint.                                                      |
| `npm run lint:fix`             | Запуск ESLint с автоматическим исправлением поддерживаемых замечаний. |
| `npm run lint:fsd`             | Отдельная проверка архитектуры FSD через Steiger.                     |
| `npm run lint:fsd:watch`       | Проверка FSD с повторным запуском при изменении исходников.           |
| `npm run format`               | Форматирование файлов через Prettier.                                 |
| `npm run format:check`         | Проверка форматирования без изменения файлов.                         |
| `npm run fix`                  | Последовательный запуск `lint:fix` и `format`.                        |
| `npm run typecheck`            | Проверка TypeScript командой `tsc -b`.                                |
| `npm run check:no-direct-urls` | Проверка прямых URL в исходниках согласно правилам проекта.           |
| `npm run check`                | Последовательный запуск ESLint, Prettier, TypeScript и проверки URL.  |
| `npm run api:generate`         | Генерация всех API-клиентов Orval.                                    |
| `npm run api:auth`             | Генерация auth-клиента.                                               |
| `npm run api:locations`        | Генерация locations-клиента.                                          |
| `npm run api:profile`          | Генерация profile-клиента.                                            |

`preview` требует предварительной сборки и предназначен для локальной проверки. На сервере статические файлы приложения обслуживает Nginx.

`check` запускает проверки по порядку и останавливается на первой ошибке. Steiger в эту команду не включён: архитектурные замечания разбираются отдельно.

## Форматирование и качество кода

| Инструмент    | Ответственность                                                      | Конфигурация                                               |
| ------------- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| Prettier      | Форматирование кода и документации.                                  | `.prettierrc`, `.prettierignore`                           |
| ESLint        | Статический анализ, правила React/TypeScript и ограничения импортов. | `eslint.config.js`                                         |
| Perfectionist | Сортировка импортов в файлах TypeScript и TSX через ESLint.          | `perfectionist/sort-imports` в `eslint.config.js`          |
| Steiger       | Проверка структуры и зависимостей по правилам FSD.                   | `steiger.config.js`                                        |
| TypeScript    | Проверка типов.                                                      | `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json` |

### Prettier

Настройки `.prettierrc`:

| Настройка       | Значение | Результат                                                              |
| --------------- | -------- | ---------------------------------------------------------------------- |
| `singleQuote`   | `true`   | Одинарные кавычки там, где это поддерживает форматтер.                 |
| `semi`          | `true`   | Точки с запятой в JavaScript и TypeScript.                             |
| `trailingComma` | `"all"`  | Завершающие запятые во всех поддерживаемых многострочных конструкциях. |
| `printWidth`    | `100`    | Предпочтительная ширина строки; это не строгий предел длины.           |
| `tabWidth`      | `2`      | Отступ в два пробела.                                                  |
| `useTabs`       | `false`  | Пробелы вместо табуляции.                                              |
| `endOfLine`     | `"lf"`   | Окончания строк LF.                                                    |

`npm run format` форматирует поддерживаемые файлы проекта, включая Markdown, JSON и стили. `npm run format:check` только проверяет их и возвращает ошибку, если требуется форматирование.

В `.prettierignore` исключены `node_modules`, `dist`, `coverage`, `src/shared/api/generated/**`, файлы `*.tsbuildinfo` и `package-lock.json`. Сгенерированные API-клиенты обновляются через Orval; lock-файл — через npm.

В конце конфигурации ESLint подключён `eslint-config-prettier`: он отключает конфликтующие с Prettier правила ESLint. Сам Prettier запускается отдельными командами.

### Порядок импортов

Правило `perfectionist/sort-imports` сортирует импорты по алфавиту по возрастанию и разделяет группы пустой строкой. Alias `@/` распознаётся как внутренний импорт.

В конфигурации задан следующий порядок групп:

1. Встроенные модули и внешние пакеты, включая их типы.
2. Внутренние импорты через `@/`, включая типы.
3. Относительные импорты из родительского и текущего каталогов, включая типы и `index`.
4. Импорты ради побочного эффекта.
5. Стили.
6. Стили, импортируемые ради побочного эффекта.
7. Остальные импорты.

`sortSideEffects: false` отключает сортировку импортов ради побочного эффекта. При ручных изменениях таких импортов учитывайте порядок инициализации модулей и подключения стилей.

`npm run lint` сообщает о нарушениях порядка импортов. `npm run lint:fix` применяет автоматические исправления ESLint и Perfectionist, а `npm run fix` затем запускает Prettier. Если `lint:fix` завершится с ошибкой, форматирование в составе `fix` не запустится.

## Проверка архитектуры FSD

Steiger подключён с рекомендуемыми правилами `@feature-sliced/steiger-plugin`. Конфигурация находится в `steiger.config.js`, проверка запускается для `src`:

```bash
npm run lint:fsd
```

Для проверки во время работы:

```bash
npm run lint:fsd:watch
```

Steiger проверяет направление зависимостей между слоями, импорты между slices одного слоя, использование public API и структуру сегментов.

В конфигурации исключены `src/shared/api/generated/**` и `**/__mocks__/**`. Для путей `src/shared/assets/**` и `src/shared/styles/**` отключено только правило `fsd/public-api`; остальные правила сохраняются.

Текущая структура проекта ещё содержит архитектурные нарушения. Их исправляют постепенно отдельными задачами и небольшими PR: например, переходят на public API, устраняют запрещённые зависимости или переносят код в подходящие сегменты. Подключение Steiger не означает, что весь проект уже соответствует FSD.

Steiger запускается отдельно и пока не включён в `npm run check`, `npm run fix` и CI. `lint:fix` не исправляет его замечания: перемещение файлов и изменение архитектурных зависимостей выполняются вручную с проверкой затронутых сценариев.

## Структура проекта

Проект использует слои Feature-Sliced Design и существующие каталоги компонентов, сервисов и хранилищ.

| Путь                       | Назначение                                                         |
| -------------------------- | ------------------------------------------------------------------ |
| `src/pages`                | Страницы приложения.                                               |
| `src/widgets`              | Крупные блоки интерфейса, включая конструктор путешествия.         |
| `src/features`             | Логика отдельных возможностей, включая перевод ошибок авторизации. |
| `src/entities`             | Модели и компоненты предметных сущностей.                          |
| `src/components`           | Существующие компоненты интерфейса и модальные окна.               |
| `src/services`             | Функции работы с API для компонентов и хранилищ.                   |
| `src/store`                | Zustand-хранилища.                                                 |
| `src/hooks`                | Общие существующие хуки приложения.                                |
| `src/shared/api`           | HTTP-клиент, нормализация ошибок, события сессии и API-адаптеры.   |
| `src/shared/api/generated` | Сгенерированные Orval-клиенты и типы.                              |
| `src/shared/ui`            | Переиспользуемые UI-компоненты.                                    |
| `src/shared/notifications` | Контекст уведомлений и шина глобальных сообщений.                  |
| `src/shared/errors`        | Error Boundary для ошибок React.                                   |
| `public`                   | Статические ресурсы.                                               |
| `scripts`                  | Вспомогательные проверки проекта.                                  |
| `.github/workflows`        | Настройки CI/CD.                                                   |

Alias `@/` указывает на `src/`. В TypeScript он задан через `paths`, в Vite — через `resolve.alias`.

## Маршрутизация и загрузка

Маршруты описаны в `src/router.tsx`. Страницы загружаются через `React.lazy`, а `Suspense` показывает `Loading page...` до загрузки модуля страницы.

## Уведомления

Toast-система использует Context API. `NotificationProvider` подключён в `src/main.tsx`, хранит список уведомлений и передаёт их в `ToastContainer`.

| Файл                                               | Назначение                                               |
| -------------------------------------------------- | -------------------------------------------------------- |
| `src/shared/notifications/NotificationContext.tsx` | Контекст и провайдер уведомлений.                        |
| `src/shared/notifications/ToastContainer.tsx`      | Отображение списка toast-сообщений.                      |
| `src/shared/notifications/notifyBus.ts`            | Связь провайдера с кодом вне React через `notifyGlobal`. |

Поддерживаются уведомления типов `success`, `error` и `info`.

## Error Boundary

`src/shared/errors/ErrorBoundary.tsx` подключён в `src/main.tsx` и оборачивает приложение. При ошибке рендеринга дочерних React-компонентов он показывает резервный интерфейс с кнопкой перезагрузки и записывает ошибку в консоль.

Error Boundary не заменяет обработку ошибок HTTP-запросов и асинхронных обработчиков. Такие ошибки обрабатываются через `try/catch`, общий API-клиент и состояние формы. Подробнее — в [обработке ошибок API](api.md#обработка-ошибок).

## Правила импортов

- UI вызывает функции из `src/services`.
- Прямой импорт Axios, HTTP-клиента и исполняемого generated-кода из UI ограничен ESLint.
- В сервисах и внутри `shared/api` HTTP-клиенты разрешены.
- Типы generated-контрактов можно импортировать через `import type`.
- Обработчики ошибок доступны компонентам, которым требуется показать сообщение пользователю.

## Проверки перед PR

```bash
npm run check
npm run build
git diff --check
```

`check` включает проверку форматирования без изменения файлов. Если она не проходит, отформатируйте нужные файлы и повторите проверку.

При изменениях структуры каталогов, public API или зависимостей дополнительно запустите `npm run lint:fsd` и проверьте замечания для затронутых модулей. Существующие FSD-нарушения устраняются постепенно; эта проверка пока не является общим блокирующим этапом CI.
