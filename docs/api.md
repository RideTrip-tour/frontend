# API и авторизация

[← Главная документация](../README.md)

Описание текущей интеграции фронтенда с API. Для генерации клиентов и проверки сетевых сценариев нужен доступ к серверу API.

## Окружение и API

### Локальная разработка

В `.env.development` задаётся адрес сервера со схемами OpenAPI:

```env
SWAGGER_API_URL=https://trip.elmobil.ru
```

`SWAGGER_API_URL` используется конфигурацией Orval при генерации клиентов. Эта переменная не определяет адрес запросов в браузере.

Адрес тестового API для локальной разработки настроен в `server.proxy` файла `vite.config.ts`. HTTP-клиент отправляет запросы на относительный путь `/api`, а Vite перенаправляет их на стенд.

### Адрес API в приложении

Функция `getApiBaseUrl()` в `src/shared/api/baseUrl.ts` использует:

- `/api`, если `VITE_API_URL` не задана;
- значение `VITE_API_URL` с добавленным `/api`, если переменная задана.

Обычная конфигурация проекта не требует `VITE_API_URL`. Если нужен отдельный адрес шлюза, указывайте его без завершающего `/api`: этот префикс добавляется кодом.

Переменные `VITE_*` подставляются при сборке приложения.

### Маршрутизация на сервере

После деплоя браузер отправляет запросы `/api` на домен открытого сайта. Серверный прокси или шлюз должен направлять эти запросы в API.

Vite proxy используется при локальной разработке.

## Генерация API-клиентов

Конфигурация находится в `orval.config.js`.

| Проект Orval | Путь схемы относительно `SWAGGER_API_URL` | Результат генерации                               |
| ------------ | ----------------------------------------- | ------------------------------------------------- |
| `auth`       | `/api/auth/openapi.json`                  | `src/shared/api/generated/auth/auth.ts`           |
| `locations`  | `/api/locations/openapi.json`             | `src/shared/api/generated/locations/locations.ts` |
| `profile`    | `/api/profile/openapi.json`               | `src/shared/api/generated/profile/profile.ts`     |

По умолчанию конфигурация загружает `.env.development`. Если задан `NODE_ENV`, она выбирает `.env.<NODE_ENV>`. `SWAGGER_API_URL` также можно передать через окружение процесса.

Для обновления клиентов:

```bash
npm run api:generate
npm run check
npm run build
```

Сгенерированные файлы хранятся в Git. После генерации проверьте diff и закоммитьте изменения. Не редактируйте generated-файлы вручную: следующая генерация перезапишет правки.

Каталог `src/shared/api/generated/**` исключён из ESLint, Prettier и Steiger. Сгенерированный код продолжает участвовать в проверке TypeScript и сборке. Обёртки и остальной код `src/shared/api` проверяются обычными инструментами проекта.

Генерация не запускается автоматически при сборке. CI использует уже закоммиченные клиенты и не зависит от доступности сервера OpenAPI в момент сборки.

Orval зафиксирован на версии `8.37.0`. Обновляйте генератор отдельно с повторной генерацией, проверкой diff и сборкой.

### Статус интеграции

- `authService` использует Orval для входа, регистрации, восстановления пароля, подтверждения почты и выхода.
- `usersService` использует Orval для получения текущего пользователя, смены пароля и запроса изменения email.
- Клиенты `locations` и `profile` пока только сгенерированы и не подключены к рабочим сервисам и интерфейсу.

## HTTP-клиент и авторизация

Основной клиент находится в `src/shared/api/client.ts`. Для запросов заданы `withCredentials: true`, таймаут 10 секунд и заголовок `Accept: application/json`. Общий `Content-Type` не зафиксирован: формат зависит от запроса; например, вход отправляется как `application/x-www-form-urlencoded`.

Авторизация работает через cookie: access token имеет формат JWT, а для обновления сессии используется refresh. Фронтенд не добавляет access token в заголовок `Authorization`: отправкой cookie управляет браузер. Interceptor обрабатывает ответы и обновляет сессию, а не подставляет JWT в заголовки.

Адаптер `src/shared/api/auth/authApi.ts` подключает сгенерированный auth-клиент к общему `apiClient`. Для запросов Orval применяется `authRequestOptions`, чтобы не добавлять `/api` дважды: этот префикс уже присутствует в generated-путях.

При ответе `401` на запрос, допускающий обновление сессии:

1. Отдельный HTTP-клиент вызывает `/api/auth/refresh` без interceptor основного клиента.
2. Параллельные запросы ожидают общий `refreshPromise`.
3. После успешного refresh исходные запросы повторяются один раз.
4. При ошибке refresh ожидающие запросы отклоняются, а локальное состояние авторизации сбрасывается.
5. Повторный `401` после refresh также завершает локальную сессию.

Запросы входа, регистрации и другие auth-операции из списка исключений не запускают автоматический refresh.

Об окончании сессии клиент сообщает через `sessionEvents.ts`. Обработчик зарегистрирован в `authStore.ts`; HTTP-клиент не импортирует Zustand-хранилище.

Zustand persist сохраняет в `localStorage` данные пользователя и признак авторизации. Это не хранение токенов и не подтверждение действительности серверной сессии: при запуске приложения выполняется запрос текущего пользователя.

## Обработка ошибок

`src/shared/api/errors.ts` нормализует ошибки в `ApiError`, сохраняя сообщение, статус, данные ответа, URL и категорию ошибки. Сетевые ошибки, таймауты и серверные ошибки могут передаваться в глобальную систему уведомлений.

Перевод известных кодов авторизации находится в `src/features/auth`:

- `model/authErrorCodes.ts` — словарь сообщений;
- `lib/getAuthApiErrorMessage.ts` — выбор сообщения для формы.

Сервисы пробрасывают нормализованную ошибку через `throw handleApiError(error)`. Компоненты авторизации получают текст через `getAuthApiErrorMessage(error)` и записывают его в состояние формы. Для неизвестных кодов сохраняется сообщение общего обработчика.

Ошибки подтверждения регистрации обрабатываются отдельно: интерфейс учитывает некорректную ссылку и возможность повтора после временной ошибки.

Toast-система использует Context API и шину `notifyGlobal`; подробности — в [разделе уведомлений](development.md#уведомления).

[Error Boundary](development.md#error-boundary) отвечает за ошибки рендеринга React; обработка ошибок API выполняется в HTTP-клиенте, сервисах и формах.
